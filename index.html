Live Orders

Real-time order board

When staff move an order, the counter, the board and any connected system see it within a second, with no reload. Customers browse the parts catalog and build a counter order.

  • Real time that survives dropped connections: events have a sequence number and the board catches up on what it missed.
  • WebSockets open with one-time tickets, so the session token never reaches the browser.
  • Signed incoming and outgoing webhooks, retried with a queue; outgoing ones refuse internal addresses.
  • NestJS
  • WebSocket
  • Redis
  • BullMQ
  • PostgreSQL
  • Next.js

Stock Manager

Inventory control with microservices

Products, stock in and out, low-stock alerts, roles (admin, operator and read-only), an audit trail of who changed what and when, a dashboard and an inventory report with restock suggestions and AI analysis.

  • Three NestJS services behind an nginx gateway; each owns its data, and reports reads stock over HTTP.
  • Stock can never go below zero, even with two withdrawals at once: the database enforces it and a test fails if the guard is removed.
  • Passwords hashed with scrypt, tokens signed with RS256, lockout after repeated failed sign-ins.
  • Browser tests run in CI against the full Docker stack.
  • NestJS
  • Prisma
  • PostgreSQL
  • Next.js
  • Docker
  • Playwright
  • GitHub Actions

How I work

The same habits in both repositories.

  • Rules live in the backendBusiness rules sit in tested domain classes on the service that owns the data, never only in the screen.
  • A test for every rule and fixUnit tests per rule, integration tests against real PostgreSQL and Redis, and a failing test before each bug fix.
  • Errors people can act onEvery error has a stable code that the frontend translates into English or Portuguese.
  • AI agents with reviewI use Claude Code with written skills and independent review agents; every change still passes tests, lint and a human read.
